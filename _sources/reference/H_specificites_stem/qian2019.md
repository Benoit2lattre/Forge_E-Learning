# Retour ciblé sur les erreurs fréquentes en programmation (Qian et Lehman, 2019)

Qian, Y. et Lehman, J. D. (2019). Using Targeted Feedback to Address Common Student Misconceptions in Introductory Programming: A Data-Driven Approach. *SAGE Open*, 9(4), 1-20. [DOI](https://doi.org/10.1177/2158244019885136)

**En une phrase.** Dans un système de correction automatique de programmes Java, des messages rédigés pour chaque erreur fréquente repérée lors d'une première session sont suivis de plus de corrections à l'essai suivant (58 % contre 38 % pour les erreurs fréquentes de la session sans message) ; l'étude, petite et sans groupe témoin tiré au sort, donne surtout une démarche : catalogue d'erreurs tiré des données, message par erreur, taux de correction par message.

## Ce que fait l'étude

- **Public** (p. 4) : stage d'été résidentiel pour lycéens à haut potentiel, deux sessions de deux semaines ; groupe 1, 13 élèves (2 exclus : triche, niveau hors norme), groupe 2, 10 élèves. Cours de 3 h par matin, dont environ une heure d'exercices sur Mulberry (51 problèmes, tests d'entrée et de sortie, essais illimités) (p. 4-5).
- **Étape 1** (p. 6) : le groupe 1 ne reçoit que « il y a une erreur, réessaie ». Les erreurs fréquentes sont ensuite tirées de 4 873 solutions de 55 élèves (p. 15) : 15 erreurs de compilation et 10 erreurs de résultat (tableau 1), rattachées à des conceptions erronées (variables, expressions, structure du programme, entrées-sorties).
- **Étape 2** (p. 6-7) : le groupe 2 reçoit un message ciblé pour chaque erreur fréquente : 8 messages pour 14 erreurs de compilation, 10 pour les erreurs de résultat ; aucun message pour « { expected », dont les causes sont trop variées.
- **Mesure** (p. 7) : une solution fausse est « améliorée » si la suivante est juste, ou compile alors qu'elle ne compilait pas. Tests du khi-deux sur les solutions ; analyse qualitative de quatre messages (meilleur et pire taux de correction).

## Résultats

| Comparaison (p. 9-10) | Améliorées | Taux | Khi-deux |
| --- | --- | --- | --- |
| Toutes erreurs, groupe 1 | 176 / 521 | 34 % | |
| Toutes erreurs, groupe 2 | 177 / 397 | 45 % | χ²(1, N = 918) = 11,11, p < 0,001 |
| Erreurs fréquentes, groupe 1 (sans message) | 119 / 310 | 38 % | |
| Erreurs fréquentes, groupe 2 (avec message) | 99 / 170 | 58 % | χ²(1, N = 480) = 17,45, p < 0,001 |
| Groupe 2, erreurs sans message | 78 / 227 | 34 % | χ²(1, N = 397) = 22,42, p < 0,001 (contre 99 / 170) |

- **Exemple d'erreur fréquente** (p. 7) : sur « aire d'un triangle », 48 % des élèves obtiennent 3,16 au lieu de la bonne valeur pour l'entrée 3 4 4, parce que (a + b + c) / 2 est une division entière.
- **Taux de correction par message** (tableau 2, p. 11) : de 43 % à 83 % pour les erreurs de compilation, de 17 % à 83 % pour les erreurs de résultat (messages affichés assez souvent). Le meilleur message donne la règle et une ligne de code (division entière) ; le moins efficace porte sur la lecture d'un nombre décimal (tableau 3).
- **Analyse qualitative** (p. 11-15) : avec message, moins de solutions intermédiaires fausses avant la bonne ; certaines solutions classées « non améliorées » avaient corrigé l'erreur visée mais en gardaient une autre.

## Avis critique

**Apport.** Un cycle complet et simple : relever les erreurs fréquentes sans retour, écrire un message par erreur, mesurer le taux de correction par message. C'est exactement le cycle prévu pour ExoForge et DiagForge.

**Points forts**
- Catalogue d'erreurs et messages publiés.
- Mesure fine, à l'essai suivant, par message.
- Analyse qualitative qui montre les limites de la mesure automatique.

**Réserves**
1. **Majeure** — Pas de tirage au sort ni de groupe témoin au sens strict (les auteurs le disent, p. 15) : les deux groupes sont deux sessions successives, avec le même enseignant qui a entre-temps analysé les erreurs du groupe 1 ; son enseignement a pu changer.
2. **Majeure** — Les khi-deux traitent 918 solutions comme indépendantes alors qu'elles viennent de 23 élèves (environ 40 solutions par élève, p. 15) : les p sont très optimistes. La comparaison interne au groupe 2 oppose erreurs fréquentes et erreurs rares, qui ne sont pas de même difficulté.
3. **Importante** — Mesure de correction immédiate, pas d'apprentissage : aucune mesure différée ni de transfert.
4. **Mineure** — Public très éloigné : lycéens à haut potentiel, stage non noté, deux semaines, programmation.

**Niveau de preuve**

| Affirmation | Niveau | Raison |
| --- | --- | --- |
| Un message ciblé augmente la correction à l'essai suivant | C | Deux petites sessions non tirées au sort, analyse au mauvais niveau |
| Le retour ciblé favorise le changement conceptuel | D | Interprétation de quelques cas |
| Le taux de correction par message repère les messages faibles | C | Indicateur descriptif utile, non validé |

**Transférabilité** : moyenne. Le mécanisme (message par erreur reconnue dans un exercice à essais multiples) se transpose à ExoForge ; la valeur chiffrée ne se transpose pas. L'erreur de division entière a un équivalent direct dans nos exercices numériques (unités, degrés et radians).

**Pour conclure, il faudrait** tirer au sort, dans ExoForge, à chaque réponse fausse reconnue, entre le message ciblé et le message général, analyser par étudiant (modèle mixte) la correction à l'essai suivant et la réussite à un exercice parallèle la semaine suivante.

## Pour Forge

- **ExoForge** : message ciblé par erreur reconnue, avec règle, contre-exemple chiffré et piste ; message général sinon (niveau C). Rejoint [Gill et Greenhow (2008)](gill2008.md) et [Sikurajapathi et al. (2020)](sikurajapathi2020.md).
- **ExoForge** : un message par conception erronée, pas de message ciblé pour un symptôme ambigu (niveau D) ; catalogue construit sur une première session sans retour ciblé (niveau C).
- **DiagForge** : taux de correction par message, avec un nombre minimal d'affichages (niveau C) ; c'est la mesure qui manque aujourd'hui pour juger les retours d'ExoForge (voir « Ce qui reste ouvert » du README de l'axe).
